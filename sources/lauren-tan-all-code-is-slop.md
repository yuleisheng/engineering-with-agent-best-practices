# Source review: Lauren Tan, *All Code Is Slop (Except Mine)*

Lauren Tan (Grok Bot, SpaceXSI), AI Engineer CODE 2026, November 11, 2026. [Standalone video](https://www.youtube.com/watch?v=O_zcc6Xl12g), published November 14, 2026. Times below refer to that video, not the conference livestream.

**Evidence reviewed:** AI Engineer's [timestamped full transcript and slide captures](https://ai.engineer/talks/O_zcc6Xl12g-all-code-is-slop-except-mine). The talk is a first-person account, with concrete examples from Grok Bot and earlier work at Cursor. It shows what one team tried; it doesn't establish which intervention caused its results. The internal implementation, bug rates, and measurement methods were not independently audited for this review.

## Claim decisions

| [2:03–2:56](https://www.youtube.com/watch?v=O_zcc6Xl12g&t=123s), [8:56–9:21](https://www.youtube.com/watch?v=O_zcc6Xl12g&t=536s): Invest in APIs and deterministic checks rather than repeatedly correcting the same mistake in prose or review. | **Keep with limits.** This fits rules with a clear pass/fail boundary. A diagnostic that points to the intended alternative is useful; a rule that cannot distinguish valid exceptions just moves judgment into waivers. Tan reserves prose for judgment; the pyramid isn't a universal ranking of every review technique. [Practice](../practices/enforce-repeatable-rules.md). |
| [4:24–4:55](https://www.youtube.com/watch?v=O_zcc6Xl12g&t=264s), [6:10–6:55](https://www.youtube.com/watch?v=O_zcc6Xl12g&t=370s): Agents copy apparent precedent; Dune names Electron runtime boundaries in its directories and blocks illegal imports. | **Keep with limits.** A maintained example reduces ambiguity, and an import check turns a naming cue into an enforceable boundary. Start with a pattern that actually causes rework. This doesn't justify making an entire repo pristine, adopting Dune, or copying its exact directory layout. [Practice](../practices/make-good-patterns-discoverable.md). |
| [5:34–6:07](https://www.youtube.com/watch?v=O_zcc6Xl12g&t=334s), [7:25–8:18](https://www.youtube.com/watch?v=O_zcc6Xl12g&t=445s): Dune confines React's `useEffect` to framework APIs; Cursor agents used timers to mask a state-management mismatch. | **Reject blanket API bans as a default.** The useful distinction is supported use versus repeated misuse. [React documents legitimate external synchronization with `useEffect`](https://react.dev/reference/react/useEffect#connecting-to-an-external-system); timers can legitimately drive delays, such as a debounce. Fix or constrain the specific misuse after providing a viable alternative. [Practice](../practices/enforce-repeatable-rules.md). |
| [6:56–7:18](https://www.youtube.com/watch?v=O_zcc6Xl12g&t=416s), [8:20–8:52](https://www.youtube.com/watch?v=O_zcc6Xl12g&t=500s): Unsolicited explanations can turn workarounds into precedents; Grok Bot bans what Tan calls 99% of comments. | **Reject a comment-removal quota or blanket ban.** Comments don't enforce behavior, but a concise explanation of an external constraint or non-obvious invariant can prevent the next maintainer from undoing an intentional choice. Keep the rationale and enforce the testable rule separately. |
| [9:40–10:46](https://www.youtube.com/watch?v=O_zcc6Xl12g&t=580s): Let agents run the app and use a feature map and reusable drivers. The team often reviews artifacts instead of code. | **Keep runtime evidence; reject artifacts as a universal substitute for code review.** A screenshot or recording can answer a behavior question but can't show every side effect, permission check, or failure path. Start with one observable assertion and an existing driver; a custom CLI is useful only if it saves repeated setup or ambiguity. [Practice](../practices/verify-real-behavior.md). |
| [10:50–11:48](https://www.youtube.com/watch?v=O_zcc6Xl12g&t=650s), [12:54–13:16](https://www.youtube.com/watch?v=O_zcc6Xl12g&t=774s): The team uses TLA+ for multi-device flows, Lean for parts of a virtualization algorithm, and property-based UI tests; user-facing statecharts help reviewers see intent. | **Keep targeted state and invariant checks; defer the tool choices to the repo.** Tan describes early successes, not a comparison with simpler tests. A chart clarifies the spec, a model checker or proof tests a modeled property, and a runtime check tests the implementation; none serves all three roles. [Practice](../practices/check-state-transitions.md). |
| [11:51–12:50](https://www.youtube.com/watch?v=O_zcc6Xl12g&t=711s): Tan cites Cindy Sridharan's 70% verification token share and says agents make heavier verification cheaper to write and maintain. | **Reject 70% as a budget target; defer the cost claim.** The ratio is an anecdote, not an optimum. Tasks and tools differ, and the team still pays to review assertions, address flakes, and maintain models. Spend on evidence that would change the shipping decision, not on a token ratio. |
| [13:32–14:51](https://www.youtube.com/watch?v=O_zcc6Xl12g&t=812s): Grok Bot shipped about 11,000 PRs in a month, reported about 0.5% reverts, and improved startup and interaction times versus launch. | **Keep measuring user outcomes; reject the figures as benchmarks or causal evidence.** PR counts depend on slicing and workload. Reverts miss regressions that get patched forward, go unnoticed, or appear later. Performance improvements on some paths don't establish overall quality, and the talk doesn't isolate what caused them. [Practice](../practices/measure-outcomes.md). |
| [15:11–15:57](https://www.youtube.com/watch?v=O_zcc6Xl12g&t=911s), [16:21–16:52](https://www.youtube.com/watch?v=O_zcc6Xl12g&t=981s): Strengthen the edit-and-check loop before scaling it; Grok Bot runs a release-triggered workflow that finds bugs, opens fixes, and automerges them. | **Keep the order; reject unattended merge as a default.** More agents replicate gaps in checks and magnify rework. The release example doesn't establish the false-positive rate, risks outside tested scope, or controls needed elsewhere. The catalog starts with bounded, human-reviewed drafts, not the team's production workflow. [Practice](../practices/validate-before-scaling.md). |
